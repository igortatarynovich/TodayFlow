## 0. Принцип (не каталог)

| Было | Стало |
|------|--------|
| Каталог → фильтры по типу → десятки карточек → выбор контента | **Что нужно сейчас → подходящая практика → выполнение → фиксация изменения состояния** |

Пользователь выбирает **результат / потребность** (need), не тип контента. Формат подбирается **внутри** рекомендации под выбранный need и доступен как вторичный фильтр библиотеки.

Цикл:

```
need → practice → session → state check-in → save into Today
```

Практики — часть дневного контура TodayFlow, не отдельная библиотека аудио.

## 1. Locked: состояния (need) — главная навигация

Горизонтальная **скроллящаяся** лента чипов под заголовком. **SoT для Web P0 шапки.** Стабильные `id` не менять без Architecture impact + bump версии канона.

| `id` | RU label | EN label (ориентир) | Ось / смысл |
|------|----------|---------------------|-------------|
| `calm` | Успокоиться | Settle | Эмоциональная — снизить шум / тревогу |
| `focus` | Собраться | Gather | Когнитивная — фокус, собранность |
| `recover` | Восстановиться | Recover | Ресурсная — восстановление |
| `body` | Почувствовать тело | Feel the body | **Телесная** — воплощённость, контакт с телом |
| `understand` | Понять себя | Understand | **Рефлексивная** — ясность о себе |
| `sleep` | Уснуть | Sleep | Терминальная — засыпание / отпускание дня |

**Порядок чипов (обязателен):** как в таблице — `sleep` **в конце**: терминальное состояние дня завершает ряд, не теряется в середине.

### 1.1 Логика разрешения (спека ↔ макет)

«Почувствовать тело» и «Понять себя» — **разные оси потребности** (телесная vs рефлексивная). Обе — желаемые **результаты момента**, не типы контента. Отбрасывать одну ради другой = терять ось. Шестой чип допустим: лента горизонтальная и скроллящаяся.

| Источник | Что взять |
|----------|-----------|
| Макет | «Почувствовать тело» |
| Текст спеки §3.1 | «Понять себя» |
| Канон порядка | «Уснуть» в конец ряда |

**Следствие для макета (C0b DONE):** добавить чип «Понять себя»; переставить «Уснуть» в конец. Reference: Figma page `Practices / need rail` in [TODAYFLOW_FOUNDATION_UI](https://www.figma.com/design/pWdevqQqOi6wvoVc6hFWHa?node-id=7-2) · live FE `PRACTICE_NEED_IDS` / `PracticesStateCycleScreen`.

**Запрещено в need-ленте:** типы контента как замена need (медитация / йога / музыка как «состояние»); произвольные legacy goal-keys (`energy`, `growth`, …) вместо этой шестёрки.

## 2. Locked: форматы — второй уровень

Чипы **ниже** need и блока рекомендаций. Фильтруют карточки **без** перехода на тяжёлую отдельную страницу.

| `id` | RU label | Что входит |
|------|----------|------------|
| `meditation` | Медитация | Сидячие / guided mindfulness |
| `breath` | Дыхание | Breathwork, пранаяма-лайт |
| `yoga` | Йога | Йога-последовательности, asana-лайт |
| `stretch` | Растяжка | Мягкая растяжка, мобилити |
| `visualization` | Визуализация | Образные / объёмные практики |
| `affirmation` | Аффирмации | Короткие утверждения / голосовые аффирмации |
| `reflection` | Рефлексия | Письменная рефлексия, вопросы, дневник |
| `music` | Музыка | Музыка **как самостоятельная практика** (сессия звука) |
| `sleep` | Сон | Контент bedtime / звук для сна (отдельно от need `sleep`) |

**Порядок чипов:** как в таблице.

### 2.1 Логика разрешения (спека ↔ макет)

| Источник | Вердикт |
|----------|---------|
| Спека «Телесные практики» (обобщение) | **Раскрыть** по макету: отдельные чипы `yoga` и `stretch` — пользователю яснее, что получит; удобнее фильтровать библиотеку |
| Макет без «Рефлексии» / «Сна» | **Вернуть** — реальные типы контента (письмо; bedtime-звук/практики), не дубли need |
| Макет «Музыка» | **Format-чип** `music` = самостоятельные музыкальные практики. **Не отменяет** music layer §5 (сопровождение / микшер) |

**Не SoT:** единый чип «Телесные практики» как замена `yoga`+`stretch`. Соматика / body-scan без йоги-растяжки — тег/метаданные на карточке; при необходимости попадают под need `body` или ближайший format.

### 2.2 Need `body` / `sleep` vs formats

| Need | Format | Разница |
|------|--------|---------|
| `body` «Почувствовать тело» | `yoga` / `stretch` | Need = исход момента; format = способ |
| `sleep` «Уснуть» | `sleep` «Сон» | Need = «хочу уснуть»; format = фильтр bedtime-контента (в т.ч. звук для сна) |
| любой | `music` | Самостоятельная музыкальная практика ≠ слой фона в сессии (§5) |

Need первичен; format уточняет каталог.

### 2.3 Legacy catalog

Старые direction-keys и goal-ids в `practicesCatalogContent.ts` — **не SoT** шапки. Web P0: map → need/format IDs ниже; не расширять UI чипами из legacy без bump этого канона.

Пример map (ориентир): «Телесные практики» / «Движение» → `yoga`|`stretch` + need `body`; «Дыхательные практики» → `breath`; «Рефлексия»/«Дневник» → `reflection`; goal `calm` → need `calm`.

## 3. Структура экрана `/practices`

Порядок блоков (сверху вниз). Пустые условные блоки **не резервируют** место.

| # | Блок | Условие |
|---|------|---------|
| 3.1 | Заголовок + need-лента + одна карточка **«Рекомендовано сейчас»** | Всегда |
| 3.2 | **Продолжить** (in-progress) | Есть незавершённая сессия |
| 3.3 | **Практики для текущего момента** (горизонтальный скролл) | Есть кандидаты под active need |
| 3.4 | Format-чипы (второй уровень) | Всегда (фильтр) |
| 3.5 | **Практика дня** | Есть рекомендация (Today / ranker); без перегруза «алгоритмом» |
| 3.6 | **Мои практики** | Только если есть сохранённые / недавние / свои / программы |
| — | Music layer controls | В сессии и/или компактный блок на хабе — §5; не заменяет §3.1–3.5 |

### 3.1 Рекомендовано сейчас

Одна крупная карточка приложения (не лендинг-баннер): результат + длительность + формат(ы) + короткий смысл + **Начать**. Атмосферный фон допустим, без half-screen promo.

### 3.3 Карточки момента

Результат на карточке **крупнее** технической категории: не «Дыхательная практика», а «Снизить тревожность · 3 мин». Одна **активная** рекомендация (§3.1) визуально сильнее остальных.

### 3.5 Практика дня

Может учитывать настроение, время суток, карту/число дня, вечерний чек-ин, цель, выбранный need. Снаружи — простая формулировка. Механика рекомендации пользователю не объясняется.

### 3.6 Мои практики

Только после первого сохранения / прохождения / создания. Не пустой placeholder.

## 4. Экран сессии + чек-ин (замыкает цикл)

После **Начать** — почти полноэкранный режим:

- атмосферный фон · название · краткая инструкция · таймер / прогресс · крупная пауза · звук вкл/выкл (полный mix — §5) · минимум chrome

Чек-ин после завершения:

> Как вы себя чувствуете сейчас?  
> **Лучше** · **Без изменений** · **Сложнее**

Затем: **«Сохранить результат в сегодняшний день»**.

**DoD цикла (P1):** сессия + чек-ин + запись в день; без них P0 shell не замкнут.

## 5. Музыкальный слой (отдельная подсистема)

Два разных продукта одного звука:

| | Format `music` (§2) | Music layer (этот §) |
|--|---------------------|----------------------|
| Роль | Фильтр / карточки **самостоятельных** музыкальных практик | Сопровождение сессии: голос · музыка · природа |
| UI | Чип в ленте форматов | Режимы + слайдеры в сессии (и опц. на хабе) |

### 5.1 Режимы использования слоя

- фон для медитации / йоги / растяжки / визуализации
- смена по этапам сценария
- рекомендация под need / время суток / настроение
- продолжение звучания после инструкции
- (пересечение) сессия, открытая из format `music`

### 5.2 Управление звуком (в сессии)

| Режим сопровождения |
|---------------------|
| С голосом |
| Только музыка |
| Без звука |

Громкость слоёв независимо: **голос** · **музыка** · **звуки природы**; опц. таймер продолжения после практики.

**Параллельность:** M0 можно вести параллельно P0/P1.

## 6. Визуальные принципы (уточнение к Foundation)

- Не одна большая wellness-фото на весь фон страницы
- Молочно-бежевый base; лавандовые / пыльно-розовые / небесно-голубые акценты
- Крупные радиусы, мягкие тени, воздух; одна recommendation сильнее остальных
- **Desktop:** колонка ~900–1100 px; справа rail **«Сегодня»** (настроение, цель, завершённая практика, вечерний чек-ин)

Токены / motion — Foundation.

## 9. Architecture impact

- **SoT before (v1.0):** 5 needs без «Почувствовать тело»; formats с umbrella `body`; music только §5.
- **SoT after (v1.1):** 6 needs (§1, sleep last); 9 formats (§2: yoga/stretch/music chips + reflection/sleep); music = format **и** layer.
- **Public JSON changed?** C1: optional `need_ids[]`, `format_id`, `outcome_label` on PracticeResponse (backward compatible). P0/P1 — FE shell/session.
- **Migration required?** yes FE map legacy → new IDs; v1.0 `body` format → `yoga`|`stretch`; mockup needs → §1.
- **Canon updated?** yes — этот файл v1.1
- **Backward compatible?** catalog UI до P0; после P0 старые goal-chips не SoT
