## 0. Принцип (не каталог)

| Было | Стало |
|------|--------|
| Каталог → фильтры по типу → десятки карточек → выбор контента | **Что нужно сейчас → подходящая практика → выполнение → фиксация изменения состояния** |

Пользователь выбирает **результат / потребность** (need), не тип контента. Формат (дыхание, визуализация, растяжка…) подбирается **внутри** рекомендации под выбранный need.

Цикл:

```
need → practice → session → state check-in → save into Today
```

Практики — часть дневного контура TodayFlow, не отдельная библиотека аудио.

## 1. Locked: состояния (need) — главная навигация

Горизонтальная лента чипов под заголовком. **Это SoT для Web P0 шапки.** Стабильные `id` не менять без Architecture impact + bump версии канона.

| `id` | RU label | EN label (ориентир) | Смысл |
|------|----------|---------------------|--------|
| `calm` | Успокоиться | Settle | Снизить шум / тревогу |
| `focus` | Собраться | Gather | Фокус, собранность |
| `recover` | Восстановиться | Recover | Восстановление ресурса |
| `sleep` | Уснуть | Sleep | Засыпание / вечернее отпускание |
| `understand` | Понять себя | Understand | Рефлексия, ясность о себе |

**Порядок чипов:** как в таблице (слева направо).

### 1.1 Решение по расхождению с макетом

| Вариант | Вердикт |
|---------|---------|
| «Понять себя» (текст спеки §3.1) | **Включено** — need = результат |
| «Почувствовать тело» (макет) | **Отклонено** как need-чип |

**Почему:** «Почувствовать тело» — это **модальность / формат** (телесная работа), а не желаемый исход. Телесные практики живут в format `body` (§2) и могут рекомендоваться под любой need (например `recover` → мягкая растяжка). Поднимать тело в primary nav = снова навигировать по типу контента.

**Запрещено в UI need-ленты:** «Почувствовать тело», типы контента (медитация / йога / музыка), произвольные goal-keys из legacy catalog (`energy`, `growth`, …) как замена этой пятёрки.

## 2. Locked: форматы — второй уровень

Чипы **ниже** need и блока рекомендаций. Фильтруют карточки **без** перехода на тяжёлую отдельную страницу.

| `id` | RU label | Что входит |
|------|----------|------------|
| `meditation` | Медитация | Сидячие / guided mindfulness |
| `breath` | Дыхание | Breathwork, пранаяма-лайт |
| `reflection` | Рефлексия | Письменная рефлексия, вопросы, дневник |
| `affirmation` | Аффирмации | Короткие утверждения / голосовые аффирмации |
| `visualization` | Визуализация | Образные / объёмные практики |
| `body` | Телесные практики | Йога, растяжка, соматика, разминка, сканирование тела |
| `sleep` | Сон | Практики, явно размеченные под засыпание / bedtime |

**Порядок чипов:** как в таблице.

### 2.1 Разнос макетных ярлыков (Йога / Растяжка / Аффирмации / Музыка)

| Макетный ярлык | Куда в каноне |
|----------------|---------------|
| **Йога** | Не чип. **Subtype / tag** внутри format `body` (`subtype: yoga`). |
| **Растяжка** | Не чип. **Subtype / tag** внутри format `body` (`subtype: stretch`). |
| **Аффирмации** | Format-чип `affirmation` (тип практики из §2 спеки; не music). |
| **Музыка** | **Не** format-чип второго уровня. См. §5 music layer. Музыкальная **сессия как практика** — карточка с `format` одного из locked format **или** отдельный `media_role: music_session` в данных; в ленте форматов отдельного чипа «Музыка» нет. |

### 2.2 Need `sleep` vs format `sleep`

- **Need `sleep` («Уснуть»)** — «что мне нужно сейчас».
- **Format `sleep` («Сон»)** — фильтр контента, размеченного под bedtime.

Могут совпадать в рекомендации; это не дубль навигации: need первичен, format уточняет.

### 2.3 Legacy catalog

Старые direction-keys (`Движение`, `Активация`, `Осознанность`, …) и goal-ids (`calm`/`energy`/…) в `practicesCatalogContent.ts` — **не SoT** шапки. При Web P0: маппинг legacy → need/format IDs; не расширять UI новыми top-level чипами из legacy без обновления этого канона.

## 3. Структура экрана `/practices`

Порядок блоков (сверху вниз). Пустые условные блоки **не резервируют** место.

| # | Блок | Условие |
|---|------|---------|
| 3.1 | Заголовок + need-лента + одна карточка **«Рекомендовано сейчас»** | Всегда |
| 3.2 | **Продолжить** (in-progress) | Есть незавершённая сессия |
| 3.3 | **Практики для текущего момента** (горизонтальный скролл) | Есть кандидаты под active need |
| 3.4 | Format-чипы (второй уровень) | Всегда (фильтр) |
| 3.5 | **Практика дня** | Есть рекомендация (Today / ranker); без перегруза «алгоритмом» |
| 3.6 | **Мои практики** | Только если есть сохранённые / недавние / свои / программы |
| — | Music layer controls | В сессии и/или компактный блок на хабе — см. §5; не заменяет §3.1–3.5 |

### 3.1 Рекомендовано сейчас

Одна крупная карточка приложения (не лендинг-баннер): результат + длительность + формат(ы) + короткий смысл + **Начать**. Атмосферный фон допустим (градиент / фрагмент фото), без half-screen promo.

### 3.3 Карточки момента

Результат на карточке **крупнее** технической категории: не «Дыхательная практика», а «Снизить тревожность · 3 мин». Разный ритм высоты/иллюстрации допустим; одна **активная** рекомендация (§3.1) визуально сильнее всех остальных.

### 3.5 Практика дня

Может учитывать настроение, время суток, карту/число дня, вечерний чек-ин, цель, выбранный need. Снаружи — простая формулировка. Астрология / нумерология / AI **не** объясняются пользователю как алгоритм.

### 3.6 Мои практики

Появляется **только после** первого сохранения / прохождения / создания. Не пустой placeholder.

## 4. Экран сессии + чек-ин (замыкает цикл)

После **Начать** — почти полноэкранный режим (не обычная scroll-страница каталога):

- атмосферный фон
- название
- краткая инструкция
- таймер / прогресс
- крупная пауза
- звук вкл/выкл (минимум; полный mix — §5)
- минимум chrome

После завершения — чек-ин состояния:

> Как вы себя чувствуете сейчас?  
> **Лучше** · **Без изменений** · **Сложнее**

Затем: **«Сохранить результат в сегодняшний день»** — практика входит в дневной цикл Today, не остаётся сиротой в библиотеке.

**DoD цикла (отдельный инкремент после Web P0 shell):** сессия + чек-ин + запись в день обязательны; без них P0 shell не считается замкнутым продуктовым циклом.

## 5. Музыкальный слой (отдельная подсистема)

Музыка — **конструктор сопровождения / состояния**, не отдельная «библиотека треков» как главная IA экрана и **не** чип в §2.

### 5.1 Режимы использования

- самостоятельная практика (карточка практики с музыкальной ролью)
- фон для медитации / йоги / растяжки / визуализации
- смена по этапам сценария
- рекомендация под need / время суток / настроение
- продолжение звучания после завершения инструкции

### 5.2 Управление звуком (в сессии)

| Режим сопровождения | |
|---------------------|--|
| С голосом | |
| Только музыка | |
| Без звука | |

Независимая громкость слоёв: **голос** · **музыка** · **звуки природы**; опционально таймер продолжения после практики.

**Параллельность работ:** music layer можно вести параллельно Web P0 / циклу; не блокирует фиксацию need/format IDs.

## 6. Визуальные принципы (уточнение к Foundation)

- Не одна большая wellness-фотография на весь фон страницы
- Светлый молочно-бежевый base; лавандовые / пыльно-розовые / небесно-голубые акценты
- Крупные радиусы, мягкие тени, воздух
- Мало насыщенных фото; одна recommendation сильнее остальных
- **Desktop:** рабочая колонка ~900–1100 px; справа компактный rail **«Сегодня»** (настроение, цель дня, завершённая практика, вечерний чек-ин) — преимущество ширины без ощущения маркетингового сайта

Токены и motion — из Foundation; здесь только иерархия экрана.

---

## 7. Что входит в раздел (scope контента)

Не только аудиомедитации: визуализации, дыхание, аффирмации, тело / йога / растяжка, внимание и воображение, сон, энергия и концентрация, письменная рефлексия, ритуалы 2–5 мин и сессии 15–30 мин, музыка как практика и как фон.

Под одним need система **может** предложить разные formats — в этом ценность раздела.

## 9. Architecture impact (заморозка списков)

- **SoT before:** фактически catalog IA (`practicesCatalogContent` goals/directions + Practices v2 tabs/programs).
- **SoT after:** этот документ — need IDs §1 + format IDs §2; цикл §0/§4; music = §5.
- **Public JSON changed?** no в C0 (docs only). P0/P1 могут добавить/уточнить поля сессии и check-in — отдельный Architecture impact в PR кода.
- **Migration required?** yes для FE: map legacy catalog → need/format; deprecate «Почувствовать тело» и format-чипы Йога/Растяжка/Музыка в UI.
- **Canon updated?** yes — `docs/practices/PRACTICES_SCREEN_V1.md`
- **Backward compatible?** UI old catalog остаётся до P0; после P0 старые goal-chips не SoT.
