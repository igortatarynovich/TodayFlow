## 0. Зачем этот документ

Сейчас Таро в продукте выглядит как набор разных решений: сетка из пяти кнопок, одиночная рубашка, отдельный reveal-экран, иконки раскладов, emoji-фолбэки, status-точки.  
Это ломает премиальность даже при хороших ассетах.

**Задача v1:** один раз ответить на язык объекта «Таро в TodayFlow» — и только после accept реализовать **один** experience-компонент, который используется везде.

### Правило заморозки (до accept)

| Можно | Нельзя |
|-------|--------|
| Чинить баги ассетов / pipeline | Добавлять новые параллельные «веер / колода / 5 кнопок» сцены |
| Документировать и принимать этот канон | Делать отдельный UI «только для карты дня» vs «только для расклада» |
| Готовить Figma по §8 после accept | Хардкодить новый ритуал в коде до accept |

**После accept:** код = один объект + его формации. Старые ритуальные UI — deprecate / delete, не «оставить на всякий случай».

## 1. Канонический объект

### Решение v1 (предложение к accept)

> **Канон = колода на столе.**  
> Веер, линия, дуга, пара напротив — это **формации той же колоды**, а не отдельные экраны и не отдельные компоненты.

| Неверно | Верно |
|---------|--------|
| «Экран веера» → «экран колоды» → «экран flip» | Одна сцена: колода меняет формацию и состояние карт |
| Пять одинаковых кнопок в SaaS-grid | Физическая композиция рубашек с перекрытием и глубиной |
| Пустой слот до открытия | Закрытые карты уже лежат по схеме расклада |
| Рубашка только в момент выбора | Рубашка — фирменный объект языка Таро |

### Почему колода, а не «веер как единственный вид»

- Hero `/tarot` естественно читается как **предмет** (колода), а не как меню из пяти опций.
- Карта дня = колода → лёгкое расхождение верхних карт → касание → выезд → flip.
- Расклады = та же колода раскладывается в схему 1 / 3 / 5 / 2× напротив.
- Веер остаётся **одной из формаций** (deep / пять карт), не отдельной метафорой продукта.

Если product на accept выберет обратное («канон = веер»), меняется только §1 и таблица формаций — API объекта (§5) остаётся тем же.

## 2. Ответы канона (один раз)

### 2.1 Что пользователь видит впервые?

На `/tarot` — **Hero с колодой как объектом** (композиция рубашек), не ряд из пяти карт и не иконка.

Рядом текст и CTA (см. §3).

### 2.2 Как выглядит колода?

Композиция из **рубашек** (не лиц):

| Слой | Поведение |
|------|-----------|
| Центр | Почти вертикально, чуть выше соседей |
| ±1 | Под небольшими углами (~6–10°), частично перекрывают центр |
| ±2 | Видны только края / угол, сильнее утоплены в глубину |
| Общее | Мягкое перекрытие, тень стола, **без** общей рамки / card-container вокруг всей композиции |

Ощущение: физический предмет — колода TodayFlow.

### 2.3 Как выглядит рубашка?

- Единый фирменный back из web-pipeline (`…/tarot/web/back-*`, AVIF→WebP).
- Пропорция **3:5** всегда.
- Рубашка участвует в Hero, выборе расклада, pre-reveal, декоративных фрагментах (§7).
- **Запрещено:** emoji, градиент-плейсхолдер, traffic-light точка ориентации на лице.

Ориентация после раскрытия: текст («Прямое / Перевёрнутое положение») или гравюрный знак — не status-dot.

### 2.4 Как начинается ритуал?

Один жест для всех entry points (hub CTA, карта дня, вопрос→расклад):

1. Пользователь видит колоду (или уже разложенную формацию закрытых карт).
2. Primary action: **«Открыть расклад»** / **«Начать»** (copy по контексту, жест один).
3. Верхние карты **сами** чуть расходятся (медленный, весомый motion).
4. Пользователь касается одной закрытой карты.
5. Она выезжает вперёд (lift / isolate).
6. Переворачивается **на месте той же сцены**.
7. Остальные остаются лежать (приглушаются, не исчезают и не уезжают на другой экран).

### 2.5 Как карта раскрывается?

- Continuous scene: **нет** перехода «сетка → отдельный экран → новая карта в новом контейнере».
- Flip: медленный, 3D или честный 2.5D через `MotionFlip` / эквивалент; уважает `prefers-reduced-motion` (мгновенный face + без разлёта).
- Карта дня: результат **детерминирован** заранее; касание рубашки = **ритуал раскрытия**, не выбор из N исходов. UI обязан это честно говорить (одной короткой строкой под сценой).

### 2.6 Как выглядят 1, 3 и 5 карт?

Формации одной колоды (всегда рубашки до reveal):

| Схема | Формация | Заметка |
|-------|----------|---------|
| Карта дня / 1 карта | Одна карта из колоды (после лёгкого расхождения стопки) | Не «кнопка в пустоте» |
| Ситуация / препятствие / совет | Три карты дугой или мягкой линией с перекрытием | |
| Прошлое / настоящее / будущее | Три карты в линию, центр чуть выше | |
| Отношения | Две карты напротив друг друга | Симметрия, воздух между |
| Глубокий / 5 | Пять карт дугой (веер как формация) | Центр выше, края ниже |

После выбора одной карты: flip на месте; остальные остаются частью композиции.

### 2.7 Какие анимации канонические?

| Имя | Когда | Параметры (ориентир) |
|-----|--------|----------------------|
| `deck.idle` | Hero / покой | Лёгкое дыхание тени; без прыжков |
| `deck.respond` | Pointer / tilt | Центр +4–6px; задние ± пара градусов; блик по орнаменту |
| `deck.gather` | Press → переход в расклад | Колода собирается, затем раскладывается в формацию |
| `deck.part` | Старт ритуала | Верхние карты расходятся медленно |
| `card.lift` | Касание | Выбранная вперёд; остальные dim |
| `card.flip` | Reveal | На месте; лицо из web srcSet |
| `spread.settle` | После flip / multi-reveal | Остальные остаются; лёгкий settle теней |

**Запрещено:** пружинящие «прыгающие» карточки, мгновенный teleport, SaaS-hover scale на всей сетке, автопереход на другой route ради flip.

Длительности: медленные (ориентир 280–520 ms на шаг; gather/part до ~700 ms). Easing: ease-out / soft cubic, не bounce.

## 3. Hero `/tarot`

### Композиция

- Слева/центр: **колода-объект** (§2.2) — без рамки-контейнера вокруг.
- Текст:

> Задай вопрос. Карта поможет увидеть то, что уже назревает.

- Primary CTA: **Открыть расклад**
- Secondary (если есть сессия): продолжить прошлый вопрос — текстом/ссылкой, не второй колодой.

### Интерактив

- Cursor / device tilt → `deck.respond`.
- Press CTA или колоды → `deck.gather` → сцена расклада / question flow **с тем же визуальным языком** (не другая «тема карточек»).

Shell страницы (тёмный immersive vs foundation cream) — отдельный трек ([PRODUCT_EXECUTION_TRACKER](../PRODUCT_EXECUTION_TRACKER.md) · Tarot Immersive Dark Shell).  
**Этот документ фиксирует объект и жест**, не competing shell tokens.

## 4. Где ещё живёт рубашка

### 4.1 Выбор расклада

Каждый тип расклада = **мини-композиция рубашек по схеме**, не emoji и не абстрактная иконка:

- 1 · 3 линия · 3 дуга · 2 напротив · 5 дуга — см. §2.6.

### 4.2 Pre-reveal

До толкования пользователь видит **реальную раскладку закрытых карт**.  
Reveal = flip выбранной/очередной карты на месте.

### 4.3 Декор (осторожно)

Допустимо редко:

- едва заметный паттерн из фрагмента орнамента;
- крупный обрезанный орнамент сбоку секции;
- watermark за заголовком;
- маска перехода между блоками.

**Не** повторять полную рубашку десятки раз как фон.

## 5. Один component family (после accept)

Имена — рабочие; реализация только после accept.

```
TarotDeckExperience
  formation: idle_stack | part | line_1 | line_3 | arc_3 | face_off_2 | arc_5
  phase: rest | respond | gather | part | await_touch | lift | flip | settled
  cards: [{ slotId, faceDeckIndex | null, orientation?, revealed }]
  honesty?: "day_card_predetermined" | null
  onTouchSlot(slotId)
  reduceMotion
```

| Поверхность | Использование |
|-------------|----------------|
| `/tarot` Hero | `idle_stack` + respond |
| Карта дня (Today + Tarot) | `part` → touch → flip; honesty on |
| Spread ritual | formation по spreadId; multi flip |
| Spread picker | мини `formation` thumb |
| Reading result | settled faces; те же пропорции |

**Запрет после миграции:** параллельные `RitualTarotPickExperience` grid, emoji `CardVisual` fallback, отдельные «пять button в gridRoot» без этого объекта.

Ассеты: только [ASSET_PIPELINE.md](./ASSET_PIPELINE.md) web derivatives + `<picture>` density.

## 6. Честность механики

| Сценарий | Правда продукта | Язык UI |
|----------|-----------------|--------|
| Карта дня | Детерминирована (день / профиль) | «Карта дня уже собрана — выбери рубашку, через которую она откроется» |
| Расклад по вопросу | Карты расклада из engine | Касание открывает **эту** позицию; не обещать «выбор судьбы из пяти разных колод» если engine уже зафиксировал draw |
| Resume | Уже revealed | Сразу `settled` / flipped; без ложного выбора |

## 7. Связь с Foundation UI

- Тест «убрать текст — дорого ли?» применяется к колоде в покое и к pre-reveal раскладу.
- Карты = визуальная сущность, не `orbit-card` / тарифная сетка.
- Motion: весомый, редкий; не noise (§ Foundation motion).
- Natal остаётся SVG/instrument — **не** часть Tarot Design Language.
