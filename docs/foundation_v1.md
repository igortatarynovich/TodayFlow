# Foundation v1 — единый фундамент сервиса

**Status:** open (геометрия закрыта; константы — draft в §2; маршрутизация в работе)  
**SoT:** этот файл — единственный канон фундамента.  
**Gate:** hooks / семантический слой / KB-ритуалы — только когда чек-лист §5 зелёный.

Пока продукт доступен только владельцу и данные тестовые — окно закрыть фундамент целиком один раз правильно, а не по частям под каждую фичу.

Фундамент = **два слоя + маршрутизация**, всё раньше любой генеративной / интерпретационной работы:

| Слой | Суть | Статус |
|------|------|--------|
| **A. Геометрия** | координаты → UTC → позиции тел → углы | **закрыт** (§1) |
| **B. Константы** | атомарные значения астро / нумерологии / таро / цвета | **sign-off pending 3 locks** (§2.0); таро/цвет — отдельный трек |
| **C. Маршрутизация** | весь сервис читает константы из одного места | открыт (§3) |

Цепочка геометрии: ошибка в любом звене отравляет все последующие.  
Константы: только атомы; позиции и комбинации LLM компонует на лету.  
Маршрутизация: ни один генератор не хранит своё представление о значении планеты / аспекта / карты — только читает из фундамента.

## 1. Геометрия (закрыто 2026-08-01)

### 1.1 Цели

1. **Координаты места рождения** — покрытие малых городов; неоднозначные названия → явный выбор страны/региона (не тихий first-hit). Точность до улицы не нужна (центр города достаточен для домов).
2. **Позиции тел** — Swiss Ephemeris (`FLG_SWIEPH`); момент входа = корректный UTC (TZ). Silent fallback на Moshier запрещён.
3. **Углы (ASC/MC/дома)** — следствие п.1–2 + Placidus `houses_ex`; после фикса — кросс-проверка с независимым источником.

### 1.2 Чек-лист геометрии

| Критерий | Статус |
|----------|--------|
| Геокодинг малых городов; ambiguous → явный выбор | **LIVE** — Nominatim merge; `need_choice` / HTTP 409; FE persist `City, Country`. Smoke: Слуцк; Alexandria / Мозырь → choice |

## 2. Константы (атомарный слой)

Только атомарный уровень — не меняется день ото дня; авторский текст, не LLM.  
Готово к переносу в код/DATA как lookup-таблицы после sign-off владельца.

**Не храним как полный каталог:** позиции («Луна в Овне») и все комбинации. Default — Composition Engine из атомов. LLM **не** решает значение комбинации; выражает pack из [Interpretation Library](astrology/INTERPRETATION_LIBRARY_V1.md). Curated Layer 5 — только non-compositional исключения.

**Вне этого черновика (отдельный трек):** 78 карт таро; деталка `COLOR_CATALOG_V1` (уже почти в форме источника).

**Сверка орбисов:** углы/орбисы §2.4 совпадают с `DATA/astrology_reference/aspects.json` (quincunx отсутствует). Существующие `DATA/astrology_reference/*` и `DATA/reference/*/machine/*` — кандидаты на deprecate после переноса (§3).

### 2.0 Три lock-а перед lookup (2026-08-01)

Без этих решений в детерминированную таблицу попадает неоднозначность того же класса, что квинконс.

| # | Тема | Решение |
|---|------|---------|
| **L1** | Управитель знака | Поле `ruler` = **один** современный управитель. Классика — отдельное поле `ruler_classical` (только где отличается). Формулы/UI, которым нужен «управитель знака» по умолчанию, читают `ruler`. Традиционные цепи (`house_rulers.py`, profections) уже на classical — обязаны читать `ruler_classical`, не `ruler`. |
| **L2** | Естественные дома | Единый принцип: **все** дома по домицилям планеты → список `natural_houses` (не одно число). Двойное управление → два дома у всех одинаково (Меркурий III+VI, Венера II+VII, Марс I+VIII, Юпитер IX+XII, Сатурн X+XI; у светил и внешних — один). Узлы/Лилит/Хирон — `[]`. Если формуле нужен один дом — явное `natural_house_primary` (= первый в списке / «дневной» домициль), не молчаливый trim. |
| **L3** | Достоинства внешних | Уран/Нептун/Плутон: **`calibrated: false`** — в формулы не идут **экзальтация, изгнание (detriment) и падение (fall)** целиком. Домициль внешних = только через `ruler` знака (L1), без дубля в таблице достоинств для формул. |

Owner: подтвердил остальное as-is; эти три пункта — lock для правки таблиц → DATA.

### 2.7 Ретроградность (общий текст)

Ретроградность — оптическая иллюзия: планета не движется назад физически, а кажется движущейся назад с точки зрения Земли. Общий смысл для любой ретроградной планеты — тема этой планеты уходит внутрь и требует пересмотра, а не нового старта: то, что обычно направлено вовне (действие, общение, рост — в зависимости от планеты), в ретро-период разворачивается на переосмысление, доработку или встречу с прошлым. Это не «плохой» период, а период с приставкой «пере-»: пересмотреть, переделать, перепроверить, а не запускать новое в этой сфере.

## 3. Маршрутизация — один источник

Все потребители читают фундамент, не свою копию.

### Конкурирующие источники (свести)

| Домен | Конкуренты | Цель |
|-------|------------|------|
| Таро | FE `todayTarotCardsRu.ts` vs `tarot_full_deck.json` vs `DATA/reference/tarot/knowledge_v1/` vs смысл из `tarot_explainer.py` | Один SoT; остальное — производные или deprecated |
| Цвет | BE `day_color_catalog_v1.py` vs FE `todayDayColorGuide.ts` | BE catalog SoT (**20** = 8+A6+B6); FE = `COLOR_HEX` only + honest unavailable; Champagne via `day_favorable` ([COLOR_LAYER_B_V1.md](./color/COLOR_LAYER_B_V1.md)) |
| Нумерология | Векторы ритма без прозы (`NUMBER_RHYTHM_BY_VALUE`) + machine cores | Заполнить/заменить атомарной прозой из §2.8 |
| Астро reference | `DATA/astrology_reference/*`, `DATA/reference/astrology/machine/*` | Identity/орбис → §2; **смысл** → [Interpretation Library](astrology/INTERPRETATION_LIBRARY_V1.md) |
| Валентность аспектов | Литералы в `sphere_score_v0` / `top_driver_v1` | Lookup из §2.4 / `aspects.json` |

### Принцип

Ни один генератор (`day_scenario`, chorus, explainers, `hook_reveal`, `domain_verdicts`, …) не хранит собственное значение планеты / знака / аспекта / числа / карты / цвета. Identity/константы — из фундамента; астрологический *смысл* — из Interpretation Library; генератор только выражает pack.

Аналог правила `day_facts_v1` как SoT дня — уровнем ниже, для строительных блоков.  
Новые генераторы: документ + тест на чтение из фундамента (§5).
