# Foundation v1 — геометрия + константы + единый источник для всего сервиса

**Status:** open (geometry closed; constants + routing pending)  
**Extends:** [audits/GEOMETRY_FOUNDATION_CLOSEOUT_V1.md](./audits/GEOMETRY_FOUNDATION_CLOSEOUT_V1.md)  
**Gate:** hooks / semantic layer / KB-driven rituals only after the checklist below is green.

Пока продукт доступен только владельцу и данные тестовые — окно закрыть фундамент целиком, а не только геометрию, и сделать это один раз правильно, а не по частям под каждую будущую фичу.

Фундамент = два слоя + маршрутизация; всё это раньше любой генеративной / интерпретационной работы:

1. **Геометрия** (координаты → UTC → позиции тел → углы) — [GEOMETRY_FOUNDATION_CLOSEOUT_V1](./audits/GEOMETRY_FOUNDATION_CLOSEOUT_V1.md), **закрыто 2026-08-01**.
2. **Константы** (астрология, нумерология, и та же категория — таро, цвет) — §1 ниже.
3. **Маршрутизация** — весь сервис читает константы из одного места, не изобретает их заново в каждом потребителе — §2.

---

## 1. Слой констант — что входит

Только **атомарный** уровень — то, что реально никогда не меняется и достаточно мало, чтобы написать и провалидировать вручную за разумное время.

**Не храним:** позиции («Луна в Овне») и комбинации. LLM синтезирует их на лету из атомарных примитивов; тысячи готовых трактовок дороже и хуже, чем компоновать по запросу.

### Астрология

- **Знаки** (12): стихия, модальность, полярность, управитель, символ, ключевые темы/слова.
- **Планеты** (10, плюс узлы / Лилит / Хирон, если используются): архетип, психологическая функция, скорость, естественный дом, ключевые слова.
- **Дома** (12): значение, сферы жизни, ключевые темы.
- **Типы аспектов** (~10): угол, допустимый орбис, гармоничный/напряжённый, базовая трактовка.
  - **Квинконс (150°):** решение зафиксировано — **out of scope v1** (не в `aspects.json`, не в activation geometry / valence). Справочник и формулы должны совпадать: нигде не «есть», если в SoT вычеркнут. Пересмотр только явной калибровкой + Architecture impact.
- **Эссенциальные достоинства** (домициль / экзальтация / изгнание / падение) — кросс-таблица планета×знак; сама система фиксирована и маленькая.
- **Фазы Луны** (~8): название, психологические особенности, рекомендуемые действия.
- **Правила ретроградности** — общий текст, один на все планеты, не по каждой отдельно.

### Нумерология

- Значения чисел **1–9**: архетип, сильные/слабые стороны, ключевые слова.
- Мастер-числа **11 / 22 / 33** (/44, если используется).
- Кармические долги **13 / 14 / 16 / 19**.
- Формулы циклов (жизненный путь, число души, число судьбы, личный год/месяц/день, универсальный год/месяц/день) — математика уже фиксирована; убедиться, что нигде не пересчитываются вручную / по-разному в разных местах кода.

### Та же природа (статичный факт, не генерация)

- **Таро** — базовое значение 78 карт (или столько, сколько в live-колоде: major-only vs полная — открытый объём, не блокирует астро/нумерологию). Отдельная задача по объёму.
- **Цвет** — `COLOR_CATALOG_V1` / `day_color_catalog_v1` уже почти в нужном виде; явно входит в фундамент как источник, а не отдельный проект.

## 2. Маршрутизация — один источник для всего сервиса

Мало написать константы — нужно, чтобы **все** потребители читали именно их, а не свою копию.

### Известные конкурирующие / дублирующие источники

| Домен | Конкуренты | Цель |
|-------|------------|------|
| Таро | FE `todayTarotCardsRu.ts` vs `tarot_full_deck.json` vs `DATA/reference/tarot/knowledge_v1/` vs «канонический смысл» из `tarot_explainer.py` | Один авторитетный SoT; остальные — производные или deprecated |
| Цвет | BE `day_color_catalog_v1.py` vs FE `todayDayColorGuide.ts` | Оставить BE catalog; FE guide убрать / сделать thin client |
| Нумерология | Сейчас в основном векторы ритма без прозы (`NUMBER_RHYTHM_BY_VALUE`) | Не конкурент, а пустое место — заполнить атомарной прозой |
| Валентность аспектов | Литералы в `sphere_score_v0` / `top_driver_v1` (`trine, sextile → +1` и т.п.) | Lookup из справочника типов аспектов; формула не хранит свою копию характера аспекта |

### Принцип на будущее

Ни один генератор (`day_scenario`, chorus, explainers, `hook_reveal`, `domain_verdicts`, …) **не имеет права** хранить собственное представление о том, что означает планета / знак / аспект / число / карта / цвет. Он получает это из фундамента как структурированный контекст и только компонует текст.

Это то же правило, что уже применено к `day_facts_v1` как единственному SoT для дня — уровнем ниже, для строительных блоков дня.

Новые генераторы обязаны читать константы из фундамента — зафиксировать документом + тестом (см. чек-лист).

## 3. Порядок работ

1. **Геометрия** — закрыта ([GEOMETRY_FOUNDATION_CLOSEOUT_V1](./audits/GEOMETRY_FOUNDATION_CLOSEOUT_V1.md)).
2. **Атомарные таблицы констант** (астрология + нумерология) — авторская работа, не код; базовый слой ~1 день; таро — отдельно и дольше.
3. **Консолидация источников** (таро / цвет) → один SoT, остальные deprecate.
4. **Формулы на lookup** — `sphere_score_v0` / `top_driver_v1` и explainers читают фундамент вместо захардкоженных литералов.
5. **Только после этого** — возврат к семантическому слою и крючкам (карта / число / цвет как ритуалы).

- [ ] Конкурирующие источники таро / цвета сведены к одному авторитетному; остальные deprecated или удалены.
- [ ] Явно зафиксировано (документ + тест), что новые генераторы обязаны читать константы из фундамента — не изобретать свои.

## Architecture impact (when implementing)

Любой PR, который вводит SoT констант, меняет lookup формул или депрекейтит FE/BE дубликаты, обязан заполнить Architecture impact по `AGENTS.md` (SoT before/after, public contract, migration, canon path, backward compatibility).
