## 0. Это не экран — это Character Engine

Документ описывает **не** IA вкладки Profile.

Он описывает **движок личности**: единую модель человека, которая становится Source of Truth для всей платформы.

| Сущность | Роль |
|----------|------|
| **Character Engine** | Строит и хранит единую модель личности |
| **Profile** | Первая UI-проекция этой модели («книга характера») |
| **Today · Compatibility · Tarot · AI Coach · Future Timeline · Life Cycles · …** | Читают ту же модель; **не** интерпретируют личность заново |

Это главный архитектурный скачок TodayFlow:

> Платформа перестаёт быть набором отдельных AI-экранов.  
> Существует **одна модель человека**; все продукты работают поверх неё.

### Один вопрос движка

> **Кто этот человек?**

| Character Engine — это | Character Engine — это не |
|------------------------|---------------------------|
| Единая модель личности | Набор характеристик |
| Сценарий характера | Расшифровка натальной карты |
| Внутреннее устройство → проявления → выводы | Энциклопедия источников |
| Один движок, много проекций | Независимые генераторы «отношений / карьеры / энергии» |
| SoT платформы | SoT только экрана `/profile` |

## 1. Главное правило (каскад)

Как и в Day Engine, **ничего не существует отдельно**.

```text
Raw Sources
        ↓
Evidence Graph
        ↓
Ядро личности (одна мысль)          ← SoT модели
        ↓
Драматургия источников (Акт II)
        ↓
Internal Engine (Акт III)
        ↓
Противоречия (главное + вторичные)
        ↓
Жизненные сцены (проявления)
        ↓
Потенциал · Слепые зоны
        ↓
Компас  ← только вычисление, без LLM-промпта
        ↓
Путь личности (Финал)
        ↓
Проекции: Profile · Today · Compat · Tarot · …
```

### Запрещённые независимые генераторы (смысловые корни)

После принятия этого канона **не существуют** как самостоятельные смысловые сущности / собственные промпт-корни:

- Relationships · Career · Money  
- Strengths · Communication · Learning · Energy · Red Flags · Work Style  
- любые будущие «сферы» / «советы» / «стили» вне каскада  

Остаётся **один Character Engine**, который строит:

1. факты (Raw Sources);  
2. карту доказательств (Evidence Graph);  
3. ядро личности;  
4. роли источников;  
5. Internal Engine;  
6. ключевые противоречия;  
7. проявления в жизненных сценах;  
8. потенциал;  
9. слепые зоны;  
10. компас (derived).

Все экраны **лишь читают** уже построенную модель и показывают разные проекции.

Если блок можно сгенерировать, не читая ядро и каскад выше — это дефект архитектуры, не «удобный контракт».

**Различие с Surface Journey:** Шаги 1–5 описывают *ощущение скролла Profile*. Этот документ — *порядок смысла платформы*. UI journey проецирует акты, не подменяет движок.

## 2. Сценарий (акты)

### Пролог — два слоя исходных данных

Не один «knowledge pack», а **два слоя**. LLM интерпретации **не** читает сырую карту как стену текста — он читает структурированные доказательства.

#### Слой A — Raw Sources

Чистые факты / расчёты. **Без** единой интерпретации личности.

- натальная карта;  
- астрология (расчётные ключи);  
- китайская система;  
- тибетская система;  
- нумерология;  
- жизненные циклы;  
- архетипы;  
- культурные каталоги.

Связь с кодом: `natal_facts` + reference lookups + capability gates — без personality prose.

#### Слой B — Evidence Graph

Не список фактов, а **карта происхождения** будущих выводов.

Каждый кандидатный тезис личности связывается с подтверждающими источниками.

Примеры:

> Потребность в автономии подтверждается Солнцем, Марсом, числом жизненного пути и китайским циклом.

> Высокая эмоциональная чувствительность подтверждается Луной, преобладанием стихии Воды и тибетским элементом.

| Raw Sources | Evidence Graph |
|-------------|----------------|
| «что есть» | «что чем подтверждается» |
| без характера | ещё не логлайн, но уже объяснимость |
| вход расчётов | вход для Актов I+ (и для umbrella explainability) |

**Результат Пролога:** Raw Sources + Evidence Graph.  
Без этого слоя система снова скатывается в «LLM читает натал и фантазирует».

---

### Акт I — Ядро личности (одна мысль)

**Вопрос:** Кто этот человек в своей сути?

**Жёсткое правило:** ровно **одна** центральная мысль. Как логлайн фильма.

Это место чаще всего ломается: легко снова превратить ядро в список качеств.

| Плохо (анкета) | Хорошо (логлайн) |
|----------------|------------------|
| «Ты лидер, творческий, независимый, чувствительный…» | «Этот человек постоянно строит собственную систему мира и не способен долго жить внутри чужой.» |

Acceptance Акта I:

1. Можно ли сжать ответ в **одно** предложение без «и… и… и…» списка черт?  
2. Объясняет ли **весь** остальной Profile именно эту мысль?  
3. Если убрать любое «качество» из списка — остаётся ли смысл? (для логлайна — да; для анкеты — нет)

Это **Source of Truth** модели. Всё ниже либо вытекает из ядра, либо отбрасывается как чужеродное.

---

### Акт II — Драматургия источников

Источники — не справочник. Они **персонажи одной истории**, которая объясняет ядро.

Каждый источник отвечает не «за что отвечает планета в учебнике», а:

> Какую часть **этой** личности именно я сформировал?

Примеры ролей (иллюстрация, не шаблон):

| Источник | Роль в истории |
|----------|----------------|
| Солнце | задаёт направление |
| Луна | делает направление эмоционально необходимым |
| Марс | определяет способ действия |
| Число жизненного пути | объясняет, ради чего человек проходит этот путь |
| Китайский цикл | определяет стиль поведения |

Не «Луна в Рыбах».  
Не «Луна отвечает за эмоции».  
А вклад в **эту** центральную мысль (Акт I), опираясь на Evidence Graph.

#### Опоры и дома = информация о пользователе (жёстко)

Опоры (Солнце · Луна · ASC · числа · культурные ключи…) и **дома** — не учебник астрологии на экране.

Они обязаны нести **полезную информацию об этом человеке**: как именно этот факт формирует / проявляет его ядро, двигатель или главное противоречие.

| Запрещено (энциклопедия) | Обязательно (про пользователя) |
|--------------------------|--------------------------------|
| «7-й дом отвечает за партнёрство» | Что **для этого человека** означает его 7-й дом / DSC — как проявляется близость, контракт, ожидание от другого |
| «Солнце — личность и эго» | Какое **направление** задаёт его Солнце в связке с ядром (Акт I) |
| «ASC — маска / внешность» | Как **его** ASC окрашивает первый контакт, стиль входа в мир |
| Список домов 1–12 с общими дефинициями | По каждому значимому дому/углу — **личный** вклад; незначимое — omit, не filler |
| «Водолей независим» как словарная статья | Как **его** знак/стихия усиливает Evidence Graph и ядро |

Тест полезности (обязателен для любой опоры / дома на UI или в Snapshot prose):

1. Убрав имя планеты/номер дома, остаётся ли фраза **про этого человека**?  
2. Узнаёт ли человек себя — или читает Wikipedia?  
3. Связана ли опора с ядром / Evidence Graph — или висит отдельно?

Если нет — это **не опора Character Engine**, а справочник. Справочник в Profile/движке **запрещён** (каталог reference = kitchen / calc layer, не user-facing смысл).

Дома без full natal (нет времени+места) — **не показывать** и не заменять общими описаниями «что такое дома». CTA: что именно откроется **о нём** (не определение термина).

---

### Акт III — Internal Engine

**Имя канона:** Internal Engine (внутренний двигатель личности).  
Не «качества». **Правила работы** личности.

После этого акта остальные разделы должны быть **выводимы** из системы, а не заново «придуманы».

Оси двигателя (минимум смысла, не чеклист UI):

- как появляется решение;  
- как человек воспринимает информацию;  
- как реагирует на стресс;  
- как принимает риск;  
- как восстанавливается;  
- как запускается рост;  
- что приводит к выгоранию.

Это уже не описание. Это **механизм**.

---

### Акт IV — Внутренние противоречия

**Центр всей истории.** Именно напряжение даёт «это действительно про меня».

**Вопрос:** Где человек спорит сам с собой?

Не недостатки. **Внутреннее напряжение.**

#### Ранги противоречий (обязательно)

| Ранг | Роль |
|------|------|
| **Главное противоречие** | Одно фундаментальное напряжение, вокруг которого строится личность |
| **Вторичные противоречия** | Несколько дополнительных (обычно 1–3); усиливают, не конкурируют с главным |

Примеры осей (не чеклист):

- свобода ↔ стабильность;  
- разум ↔ чувства;  
- лидерство ↔ потребность в одобрении;  
- скорость ↔ глубина.

Если в тексте несколько «главных» конфликтов равного веса — Акт IV сломан (снова список).

---

### Акт V — Жизненные сцены (не сферы)

Механизм проявляется не в «разделах сайта», а в **ситуациях**.

| Устарело (ощущается как отдельные эссе) | Канон (ситуации) |
|-----------------------------------------|------------------|
| работа · отношения · деньги · творчество как корни | когда появляется ответственность; когда возникает близость; когда нужно принять риск; когда приходит успех; когда появляется неопределённость; когда возникает конкуренция; … |

Каждая сцена отвечает:

> Как **ядро + Internal Engine + главное противоречие** проявляются именно здесь?

UI **может** сгруппировать сцены под ярлыки «работа / отношения / деньги» — это presentation layer, не смысловые корни генерации.

---

### Акт VI — Потенциал

**Вопрос:** Кем человек способен стать?

Не профессии.  
Не «предназначение» как ярлык.  
**Направление роста** — что максимально раскрывает его систему (Internal Engine + разрешение главного противоречия).

---

### Акт VII — Слепые зоны

**Вопрос:** Что человек чаще всего не замечает в себе?

Не недостатки.  
**Закономерности**, которые мешают реализовать потенциал — обычно слепые стороны главного противоречия и двигателя.

---

### Акт VIII — Компас (только вычисление)

**Жёсткое правило:** у Компаса **нет собственного промпта / LLM-корня**.

```text
ядро → Internal Engine → противоречия → потенциал (+ слепые зоны)
        ↓
     Компас   ← derived / formula / projection assembly
```

Если Компас снова генерируют отдельным вызовом — через месяцы советы начнут противоречить Profile. Это регресс в набор AI-экранов.

Производные (примеры проекций, не отдельные сущности):

- лучшие условия;  
- стиль работы / общения / обучения;  
- источники энергии и способы восстановления;  
- идеальная среда;  
- триггеры и красные флаги;  
- сильные стороны;  
- направления развития.

Компас = **сборка** из уже построенной модели, не банк советов.

---

### Финал — Путь личности

Не повторение «кто ты».  
**Движение** личности во времени.

| Слабее | Сильнее (канон) |
|--------|-----------------|
| «Какую историю проживает этот человек?» | «**Какой путь проходит эта личность?**» |

История — результат.  
Путь — движение.

Финал объединяет ядро, главное противоречие и потенциал в одну дугу жизни. Пример формы (не шаблон копирайта):

> Вся жизнь этой личности — постепенный переход от поиска внешних ориентиров к созданию собственных. Поэтому почти каждый важный поворот будет возвращать человека к одному вопросу: следовать готовому пути или построить свой.

Не сегодня. Не совет дня. **Вообще.**

## 3. Кто читает модель

| Потребитель | Что делает | Что запрещено |
|-------------|------------|---------------|
| **Profile** | Первая книга / проекция каскада | Строить второй character arc |
| **Today** | Проецирует модель на день | Переинтерпретировать личность из знаков |

| **AI Coach / Future Timeline / Life Cycles / …** | Проекции той же модели | Собственные personality-корни |

Personal Model / Snapshot в коде = носитель Character Engine output. Имя в коде может эволюционировать; **смысл SoT** — этот документ.

## 5. Запреты генерации (анти-расползание)

| Запрещено | Почему |
|-----------|--------|
| Независимые генераторы Relationships / Career / Money / Strengths / Energy / … | Возврат к набору AI-экранов |
| Собственный промпт Компаса | Советы оторвутся от модели |
| Ядро = список качеств | Акт I сломан; дальше всё — анкета |
| Несколько «главных» противоречий | Теряется центр истории |
| Сферы жизни как смысловые корни | Сцены → UI-ярлыки, не наоборот |
| LLM читает только Raw Sources без Evidence Graph | Неустойчивая фантазия |
| Опора / дом = общее описание системы («дом N значит…») | Нет пользы о пользователе; регресс в энциклопедию |
| Today / Compat / Tarot строят новый character | Движок один |
| Параллельный portrait на read path модулей | Читать Snapshot движка |

Допустимо: проецировать уже построенную модель в слоты Availability Matrix / Snapshot — если слоты **заполняются из каскада**, а не независимыми корнями.

## 7. Acceptance (канон, не код)

Модель принята, если:

1. Есть **Character Engine output**, который читают ≥2 модуля без пересборки личности?  
2. Пролог имеет **оба** слоя: Raw Sources + Evidence Graph?  
3. Акт I — **одна** мысль (логлайн), не анкета?  
4. Акт II — источники как **роли в истории ядра**?  
5. Акт III = **Internal Engine** (правила), не список черт?  
6. Есть **одно** главное противоречие + вторичные?  
7. Проявления = **жизненные сцены**, а сферы — только UI?  
8. Компас **без** собственного LLM-промпта?  
9. Финал отвечает «**какой путь проходит личность**», не пересказ ядра?  
10. Нет независимых генераторов из §1?  
11. Каждая опора и каждый дом на UI — **про этого человека**, не словарная статья?

Если нет — дефект движка / генерации, не «UI polish».
